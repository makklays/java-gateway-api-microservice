# API Specification
**Автор:** Александр Кузив  
**Проект:** Secure Credit Hub

## 1. Обзор API
Данный документ представляет собой техническую спецификацию программного интерфейса (API) распределенной финтех-платформы **Secure Credit Hub**. Интерфейс спроектирован по стандартам REST с поддержкой реактивного неблокирующего стека (Spring WebFlux) для высоконагруженных узлов и синхронного взаимодействия для строго последовательных бизнес-операций.

* **Формат данных:** Все запросы и ответы используют строго `application/json`.
* **Кодировка символов:** `UTF-8`.
* **Сквозное распределенное логирование:** Каждый входящий и межсервисный запрос маркируется заголовком `X-Correlation-ID` (формат UUID). Если клиент отправляет запрос без данного заголовка, API Gateway генерирует его автоматически. Заголовок пробрасывается через всю цепочку микросервисов (`WebClient`), связывая логи в единый трассировочный трейс для сквозного аудита.

---

## 2. Методы аутентификации и авторизации
Безопасность периметра системы Secure Credit Hub обеспечивается централизованным микросервисом `Users Microservice`, выполняющим роль **OAuth2 Authorization Server**.

* **Аутентификация:** Клиент выполняет первичный запрос (ввод логина и пароля) на эндпоинт аутентификации и после успешной проверки получает структурированный stateless-токен **JWT (JSON Web Token)** с цифровой подписью.
* **Авторизация:** Для доступа к защищенным ресурсам клиент обязан передавать этот токен в каждом HTTP-заголовке: `Authorization: Bearer <token>`.
* **Ролевая модель:** Контроль доступа на уровне эндпоинтов реализован с помощью декларативной безопасности Spring Security (`@PreAuthorize`):
    * `ROLE_USER` — базовый уровень доступа клиентов (управление картами, платежи, просмотр курсов).
    * `ROLE_ADMIN` — административный уровень доступа (управление системой, ручное изменение курсов валют, запуск Саги).

## 3. Подробное описание каждого endpoint

### 👥 3.1. Users Microservice (Управление доступом)

#### Инициация входа в систему
* **HTTP Метод:** `POST`
* **Путь:** `/api/v1/auth/login`
* **Права доступа:** Публичный эндпоинт (Без авторизации)

##### Тело запроса (Request Body):
```json
{
  "username": "alex_kuziv",
  "password": "securePassword123"
}
```

##### Успешный ответ (200 OK):
```json
{
  "token_type": "Bearer",
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhbGV4X2t1eml2Iiwicm9sZXMiOlsiUk9MRV9VU0VSIl19...",
  "expires_in": 3600,
  "roles": ["ROLE_USER"]
}
```

### 💵 3.2. Currencies Microservice (Движок курсов валют)

#### Получение списка базовых валют и актуальных курсов
* **HTTP Метод:** `GET`
* **Путь:** `/api/v1/currencies/base-currencies`
* **Права доступа:** `ROLE_USER`, `ROLE_ADMIN`
* **Особенности:** Метод защищен предохранителями Resilience4j (`@CircuitBreaker` и `@Retry`). При временной сетевой недоступности или таймауте удаленного сервиса срабатывает резервный метод `fallbackBaseCurrencies`, предотвращая каскадный сбой шлюза и возвращая безопасный ответ.

##### Успешный ответ (200 OK):
```json
{
  "base": "UAH",
  "timestamp": "27.10.2026 21:54:00",
  "rates": {
    "USD": 41.25,
    "EUR": 44.80,
    "GBP": 53.40
  }
}
```

#### Получение детального курса валюты по ее коду
* **HTTP Метод:** `GET`
* **Путь:** `/api/v1/currencies/base-currencies/{code}`
* **Права доступа:** `ROLE_USER`, `ROLE_ADMIN`
* **Параметры пути:** `{code}` — трехзначный ISO-код валюты (например, `USD`, `EUR`)

##### Успешный ответ (200 OK):
```json
{
  "code": "USD",
  "buy": 41.10,
  "sell": 41.55,
  "updatedAt": "27.10.2026 21:54:00"
}
```

#### Обновление цен покупки/продажи конкретной валюты (Локальное)
* **HTTP Метод:** `PUT`
* **Путь:** `/api/v1/currencies/base-currencies/{code}`
* **Права доступа:** Только `ROLE_ADMIN`
* **Бизнес-валидация:** Поля `buy` и `sell` обязательны к заполнению и должны быть положительными числами. Курс продажи (`sell`) должен быть строго больше курса покупки (`buy`).

##### Тело запроса (Request Body):
```json
{
  "buy": 41.20,
  "sell": 41.70
}
```

##### Успешный ответ (200 OK):
```json
{
  "status": "SUCCESS",
  "code": "USD",
  "buy": 41.20,
  "sell": 41.70,
  "updatedAt": "27.10.2026 21:55:12"
}
```

#### Распределенная трансляция курса по системе (Централизованная Сага)
* **HTTP Метод:** `PUT`
* **Путь:** `/api/v1/currencies/base-currencies/{code}/propagate`
* **Права доступа:** Только `ROLE_ADMIN`
* **Особенности:** Запускает оркестрируемую Сагу. API Gateway выполняет резервное копирование старого курса из `Currencies Service`, обновляет его, а затем отправляет событие `CURRENCY_RATE_UPDATED` в модуль статистики. При возникновении любой ошибки транзакция прерывается и вызывается метод `rollbackSaga` для компенсации изменений. Если падает сам откат, инцидент изолируется в лог отказов интеграции (`/integration/failures`).

##### Тело запроса (Request Body):
```json
{
  "buy": 41.30,
  "sell": 41.85
}
```

##### Успешный ответ (200 OK):
```json
{
  "status": "SUCCESS",
  "message": "Курс успешно изменен и залогирован.",
  "correlationId": "a8b9c0d1-e2f3-4a5b-6c7d-8e9f0a1b2c3d"
}
```

### 💳 3.3. Payments Microservice (Платежные шлюзы)

#### Инициализация транзакции перевода средств
* **HTTP Метод:** `POST`
* **Путь:** `/api/v1/payments`
* **Права доступа:** `ROLE_USER`
* **Особенности:** Полностью реактивный неблокирующий эндпоинт (`Mono`). Поддерживаемые типы переводов: `SEPA`, `Bizum`, `Internal`.

##### Тело запроса (Request Body):
```json
{
  "type": "Bizum",
  "amount": 150.00,
  "currency": "EUR",
  "sourceCard": "4444555566667777",
  "targetPhoneNumber": "+34600112233"
}
```

##### Успешный ответ (200 OK):
```json
{
  "status": "PENDING",
  "message": "Payment initialization started successfully",
  "correlationId": "a8b9c0d1-e2f3-4a5b-6c7d-8e9f0a1b2c3d"
}
```

### 🪪 3.4. Credit Cards Microservice (Кредитные продукты)

#### Запрос баланса, лимитов и бонусных баллов по карте
* **HTTP Метод:** `GET`
* **Путь:** `/api/v1/cards/{cardId}/limits`
* **Права доступа:** `ROLE_USER`, `ROLE_ADMIN`
* **Параметры пути:** `{cardId}` — уникальный внутренний идентификатор или номер кредитной карты.

##### Успешный ответ (200 OK):
```json
{
  "cardId": "4444555566667777",
  "creditLimit": 50000.00,
  "availableBalance": 12500.45,
  "loyaltyPoints": 340,
  "status": "ACTIVE"
}
```

## 4. Список возможных кодов ошибок

В случае возникновения исключений или ошибок валидации система Secure Credit Hub возвращает стандартизированный JSON-ответ. Каждая ошибка жестко привязывается к сквозному идентификатору запроса (`correlationId`).

### Унифицированная структура ответа об ошибке (`ErrorResponse`)
```json
{
  "status": "STRING_ERROR_CODE",
  "message": "Понятное описание причины возникновения ошибки.",
  "timestamp": "27.10.2026 21:56:04",
  "correlationId": "a8b9c0d1-e2f3-4a5b-6c7d-8e9f0a1b2c3d"
}
```

### Карта HTTP-статусов и бизнес-кодов системы

| HTTP Статус | Бизнес-код ошибки (`status`) | Сценарий возникновения в Secure Credit Hub |
| :--- | :--- | :--- |
| **`400 Bad Request`** | `VALIDATION_FAILED` | Нарушены правила входного контракта: пропущены обязательные поля или нарушена бизнес-логика цен (например, курс продажи банка меньше или равен курсу покупки `sell <= buy`). |
| **`401 Unauthorized`** | `UNAUTHORIZED` | Запрос не содержит JWT-токен в заголовке `Authorization`, токен просрочен или повреждена его цифровая подпись. |
| **`403 Forbidden`** | `ACCESS_DENIED` | Пользователь успешно аутентифицирован, но его роль (например, `ROLE_USER`) не имеет прав вызывать данный административный эндпоинт. |
| **`404 Not Found`** | `RESOURCE_NOT_FOUND` | Запрашиваемый ресурс отсутствует в базе данных (неверный ISO-код валюты, несуществующий номер кредитной карты или ID пользователя). |
| **`500 Internal Error`** | `SAGA_ROLLED_BACK` | Произошел контролируемый сбой на одном из этапов распределенной транзакции Саги. Система успешно выполнила компенсирующие транзакции и откатила состояние данных к исходному. |
| **`500 Internal Error`** | `SERVER_ERROR` | Критический непредвиденный сбой сервера (авария БД, баг в логике). Для Саги означает сбой самого компенсирующего отката (данный инцидент экстренно направляется в DLQ). |
| **`503 Service Unav.`** | `SERVICE_DOWN` | Сработал предохранитель `Circuit Breaker` на шлюзе. Удаленный микросервис не отвечает по таймауту или упал. Запрос изолируется, защищая шлюз от перегрузки. |
